Beide Frontendbuilds, fünf UI-Pakettests, Typprüfung, Linter, Dokumentations- und Whitespaceprüfung bestanden.

Tabellen dürfen innerhalb ihres beschrifteten Arbeitsbereichs horizontal scrollen; Geldzellen werden nicht gekürzt. Manuelle Farbwahl gilt für die Finanzansichten; bei nicht verfügbarem Browserspeicher bleibt sie für die laufende Sitzung nutzbar. P4.2 bleibt bis zur gesonderten Tastaturabnahme offen.

## Reproduzierbare Prüfung

In der aktiven Arbeitskopie ausführen:

```sh
pnpm --filter @wimm/web build
pnpm --filter @wimm/desktop exec vite build
WIMM_BUILD=1 WIMM_CLIENT=web pnpm exec playwright test --workers=2 --output=test-results/web
WIMM_BUILD=1 WIMM_CLIENT=desktop pnpm exec playwright test --config tests/ui/desktop.config.ts --workers=2 --output=test-results/desktop
pnpm test:ui-unit
pnpm typecheck
pnpm lint
pnpm check:docs
git diff --check
```

Die Produktionsläufe erstellen 64 Screenshots unter `test-results/web` und `test-results/desktop`: je vier Ansichten pro Breite und Farbmodus (`konten.png`, `kategorien.png`, `empfänger.png`, `übersicht.png`). Diese temporären Prüfartefakte werden nicht versioniert; der Test erzeugt sie erneut. Visuelle Stichproben decken alle vier Breiten, beide Farbmodi und alle vier Ansichten ab. Die Kontonamenspalte behält eine lesbare Mindestbreite; in der Kontoartspalte verhindert eine eigene Einzeilenregel gequetschte Umbrüche; die unsichtbare Aktionsüberschrift bleibt innerhalb der scrollenden Tabelle und verursacht keinen Seitenüberlauf.
