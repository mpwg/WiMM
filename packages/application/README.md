# Gemeinsame Clientanwendung

AGPL-3.0-or-later. K02 trennt Clientabläufe von React. FinanceModel, FinanceHistory, AutomationModel, FinanceApplication und ProfileApplication koordinieren Befehle, bestätigten Zustand, Historie, Profil-/Tresor-/Sitzungsabläufe und Bereichswechsel. Uhr, IDs, Speicher und Hintergrundausführung sind injiziert. Die Anwendung enthält keine React-, DOM-, localStorage-, Web-Lock- oder Worker-Globals.

FinanceApplication übernimmt bestätigte Änderungsmengen direkt; spätere Lesefehler erzeugen keinen Wiederholungswrite. Schreibfehler erhalten Eingaben, stale CAS lädt kontrolliert den aktuellen Bestand. Fachliche Gegenbefehle bleiben im Fachkern. ApplicationActivity sperrt Finanzwrites und Profilwechsel gegenseitig. ProfileApplication prüft echte Tresor-/Schlüsselpaare, verlangt eine ausdrückliche Rettungsbestätigung und verwirft späte Ergebnisse nach Sitzungswechsel. Späte oder abgebrochene Importvorbereitung wird nicht angewandt.

Web-/Desktop-Einstiegspunkte komponieren die Anwendung mit konkreten Browser- und Speicheradaptern. `pnpm check:application` prüft die Architekturgrenze; `pnpm test:application` prüft browserfreie Finanz-/Profilaktionen, Konflikte und Abbruch. [K02-Abnahme](../../docs/handoffs/k02-2026-10-08.md), [K01-Verträge](../../docs/core-contracts.md), [#93](https://github.com/mpwg/WiMM/issues/93). Die TypeScript-Fachengine bleibt bis K04/K05 aktiv.
